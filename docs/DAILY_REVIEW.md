# 작업 종료 평가와 계획 수정

운영 방식: **예약 자동 실행 없음. 의미 있는 작업을 마칠 때마다 평가한다.** 같은 날 여러 번 작업하면 한국 날짜의 일지에 회차를 추가한다. 하루가 끝나기 전에는 마지막 회차까지의 평가이며 당일 전체 완료를 뜻하지 않는다.

## 평가 순서

1. **근거 확인:** Git 변경, 실행 상태, 결과 파일/설정/분할/표본 수와 생성 시점을 확인한다. 진행 중·실패·오래된 결과를 새 완료 결과로 읽지 않는다.
2. **목표와 비교:** [전략 목표표](STRATEGY.md)의 지표, [일정](ROADMAP.md)의 기한, [제출 점검표](SUBMISSION.md)의 파일을 각각 비교한다. 모델 성과·작업 완료·제출 준비를 따로 판정한다.
3. **결론 분류:** `목표 달성 / 일부 근거 / 실패 / 미측정` 중 하나를 근거와 함께 쓴다. 신뢰구간·분모·최악 구간이 없으면 그 한계를 적는다. 5 seed의 표준편차를 표본 신뢰구간으로 바꾸지 않는다.
4. **개선 실행:** 잘못된 주장·수치·코드·우선순위를 바로잡고 영향에 맞게 검증한다. 새 실험은 사전 기준과 기한을 정한 뒤 진행한다. 문서 수정만으로 모델 점수를 올렸다고 쓰지 않는다.
5. **계획 갱신:** 채택/폐기/보류한 주장, 다음 상위 3개 작업, 끝낼 시각, 중단 조건을 일지에 적는다. 변화가 있으면 전략·일정·제출 점검표·HTML의 요약을 동기화한다. 변화가 없으면 그 사실만 적는다.
6. **사용자에게 보고:** 오늘 무엇을 얻었는지, 목표와 얼마나 차이가 나는지, 내일/다음 회차 무엇을 바꾸는지 간결히 설명한다. 수상 확률·예상 점수는 근거 없이 계산하지 않는다.

## 일지 형식

`docs/daily/YYYY-MM-DD.md`에 아래 항목을 사용한다. 문서 링크는 해당 파일 기준 상대 경로로 쓴다. 예시 수치를 실측으로 남기지 않는다.

```text
# YYYY-MM-DD 작업 평가 (KST)
## 회차 N · 작업 종료 시각
- 작업 범위 / 브랜치:
- 공식 마감까지 / 내부 제출까지 남은 시간 (계산 기준 시각 포함):
- 근거: 실행 ID, 설정, 결과 파일, 명령·검증 결과

| 목표 또는 제출 항목 | 이전 | 이번 | 판정 | 한계·다음 조치 |
| ... | ... | ... | 미측정 등 | ... |

### 평가와 개선
- 새로 검증한 가설 / 기각한 가설:
- 버릴 주장 / 유지할 주장 / 보류할 주장:
- 실제 수정한 것과 확인 방법:
- 개발 데이터 선정 여부 / test 재사용 여부 / 분모와 불확실성:
- 일정 변경과 이유 / 외부 정보·사용자 행동이 필요한 항목:

### 다음 상위 3개 작업
1. 산출물, 완료 조건, 기한, 실패 시 중단/대안
2. ...
3. ...
```

점수가 오르더라도 새로운 구간에서 무너지거나 검사·경보 부담이 커지면 개선으로 단정하지 않는다. 임계값이나 목표 변경은 변경 전후·기업문제/비용 근거·변경 시점을 남긴다. 실험이 없었던 작업에서는 성과를 `변화 없음/미측정`으로 기록하고, 계획·제출물 개선만 평가한다.
