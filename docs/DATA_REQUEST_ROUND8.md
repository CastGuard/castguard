# 팀원에게 요청할 최소 자료 · 회차8 초안 / 회차10 검증 요건 반영

지금 필요한 것은 더 많은 모델 실험이 아니라, **검사 전에 무엇을 알 수 있었고 같은 검사 자원으로 언제까지 처리할 수 있었는지**를 확인할 기록이다. 아래 요청서는 보낼 준비만 했으며 외부로 전송하지 않았다. 모르는 칸은 비워 두고 “없음/확인 중”이라고 답한다. 시각·비용·서명·완료 여부를 추정으로 채우지 않는다.

## 먼저 답할 세 가지

1. #41/#42 원본 가이드/AAS·코드표와 당시 수집·검사 로그가 보관돼 있는가? 있다면 파일과 담당자/작성일을 알려 달라.
2. 실제 검사자 수·건별 검사시간·최대 대기시간·보관 가능한 수량·run 종료 잔량 처리 규칙은 무엇인가? 독립 감사 검사를 위한 별도 자원이 가능한가?
3. 기존자료와 겹치지 않는 미래 생산 기록 및 독립 품질 감사표본을 확보할 수 있는가? 가능하다면 대상 설비/제품·수집기간·기록 담당자를 정해 달라. 표본 수는 아직 확정하지 않는다.

## 전달 파일: 빈 양식8개와 계약 JSON

원본은 별도로 보존한다. 전달용 사본의 event_id는 생산 한 Shot을 고유하게 가리키고, 모든 표가 같은 ID를 사용한다. 원본 식별자는 original_event_id에 보존한다. 시각은 날짜 해석이 모호하지 않은 ISO 형식 `2026-10-10T09:30:00+09:00`처럼 시간대가 포함된 형식으로 적는다(이 날짜는 형식 설명이며 실제 기록이 아니다).

| 파일 | 한 행의 뜻 | 꼭 확인할 내용 |
|---|---|---|
| events.csv | 생산된 모든 Shot | event_id·원본ID·run_id·생산완료·생산기록 수신시각. 미검사도 포함 |
| features.csv | Shot의 입력 변수 하나 | feature·value·측정시각·수신시각. 결과/검사유무를 입력으로 섞지 않음 |
| scores.csv | 정책별·Shot별 예측 기록 | policy·event_id·점수 확정시각·priority_class·score. 모든 정책/모든 Shot을 기록하고 결손은 공통 hold |
| audit_sample.csv | 전체 Shot의 독립 감사 선택 | 선택시각·selected(True/False)·probability. 전수 또는 잠근 seed/p의 표본과 일치해야 함 |
| quality_results.csv | 독립 감사로 확인한 Shot | 검사 시작·완료·라벨 수신·y_defect(0/1). 정책이 고른 검사결과와 구분 |
| capacity_slots.csv | 공통 검사 기회 하나 | slot_id·resource_id·시작·완료시각. 별도 감사 자원과 혼동하지 않음 |
| assignments.csv | 정책별 검사 슬롯 배정 | policy·slot_id·event_id. 빈 슬롯은 event_id만 빈칸. 검사 완료가 만료/평가종료 안에 있어야 함 |
| label_uses.csv | 정책이 학습에 사용한 라벨 | policy·label_event_id·라벨 수신·사용시각. 정답을 쓰지 않는 FIFO는 행 없음 |

`sampling.definition_path`·`definition_sha256`·`event_id_rule`과 동결된 추출계획 JSON을 함께 전달한다. 계획의 여섯 키와 값/자료형은 [현행 평가 계약](FUTURE_EVALUATION_CONTRACT.md)의 규격을 따른다. 체크박스만으로 추출계획 증거를 대체하지 않는다.

policy별 definition_path·definition_sha256와 동결시각은 모델 담당자가 채운다. 정책 정의/설정 파일도 전달 폴더 안에 넣어 실제 해시가 일치하는지 검사한다. source_files에는 전달 폴더 안 원본 사본의 상대경로와 SHA256을 기록한다. 자료 책임자는 contract.json의 확인 항목을 실제 근거를 본 뒤 체크한다. 코드로 시각이나 확인항목을 생성해 빈칸을 메우지 않는다.

`python -B future_evaluation.py init --output <새폴더>`가 최신 기본 양식이다. `future_evaluation_v2.py` 명령도 같은 revision 3으로 연결된다. `templates/future_evaluation/`에는 **헤더만 있는 CSV**와 미완료 계약이 있다. 원본을 직접 고치지 말고 새 폴더로 복사해 작성한다. 기본 입력 열2개는 임시이며 실제 사용 입력과 가용 시점을 합의해 교체한다. 프로그램 사용법과 지원하는 제한은 [평가 계약](FUTURE_EVALUATION_CONTRACT.md)에 있다.

## 중단 기준

새 생산/독립 품질표본이 없으면 성능 실험은 중단한다. 시각·대기한도·검사 자원·단위를 확인할 수 없으면 해당 현장 주장을 하지 않는다. 자료가 들어오면 먼저 구조 검증과 원천 확인을 하고, 마지막 평가의 지표·성공 기준·필요 run 수를 라벨을 보기 전에 별도로 고정한다.
