과제 ② 검토용 보고서 초안

팀명과 성명 및 서명은 실제 참가자가 최종 입력한다. 이 문서에는 임의 서명이나 설문 완료 화면을 넣지 않았다.

## 내용요약

이 연구는 다이캐스팅 생산 완료 후 최종검사 전의 제한된 검사 용량을 어디에 배정할지 다룬다. 주조 품질보증 데이터를 주 데이터로, 설비 예지보전 데이터를 보조 데이터로 사용해 공정 이력과 상태 경보의 가치를 비교했다. 별도 주조 공정최적화 데이터는 변수 기여를 확인하는 보조 분석으로 사용했다.

핵심 결과는 결합 정책의 우월성을 입증하지 못했다는 것이다. 품질 모델의 이력 추가에 따른 AP 변화는 {{B_AP_GAIN}}였고, 같은 전체 타임라인에서 검사 용량을 20%로 제한한 개발 평가의 품질 포착률은 단독 Q {{Q_CAPTURE}}%, 상태 경보 추가 GQ {{GQ_CAPTURE}}%였다. 조건 이탈을 보류한 OOD05는 {{OOD05_CAPTURE}}%로 더 낮았으며 미처리 보류는 GQ {{GQ_BACKLOG}}개에서 {{OOD05_BACKLOG}}개로 증가했다.[E01,E04]

따라서 현재 정책을 자동 생산중지나 검사 대체에 채택하지 않는다. 결과의 가치는 공통 키의 검증, 정답이 없는 예열 구간의 보존, 같은 검사 용량과 전체 분모에 따른 비용 비교, 적용 전에 확보해야 할 운영 조건을 명확히 했다는 데 있다. 이미 본 데이터에 대한 회고·개발 분석이며 실제 불량률이나 비용 절감의 실측은 아니다.

공식 보고서의 공통 6장 구조를 따른다. 과제 공고의 모델/오류 배점 35/15와 양식의 40/10이 불일치하므로 배점은 미확정이다. 두 항목의 요구는 모두 다룬다. 공식 마감은 2026년 10월 8일 23:59 KST이며, 이 문서는 제출 완료를 뜻하지 않는다.[O01,O02]

## 제1장 기업문제 정의 및 데이터 통합

### 검사 대기와 적용 범위

대상 문제는 알루미늄 다이캐스팅의 생산 완료 Shot에 대한 추가검사 우선순위다. 품질 가능성이 높은 Shot에 검사 용량을 우선 배정하되, 예열 상태나 입력 결손을 무조건 정상으로 통과시키지 않는 방안을 비교한다. 현장의 현재 검사 방식, 검사 인원, 허용 대기시간, 불량 단가는 확보하지 못했다. 따라서 실제 기업의 개선 실적 대신 공개 사례 데이터에서 운영안의 성립 조건을 검증한다.

예측 시점은 현재 Shot의 공정 기록을 받은 뒤 최종검사 전에 두었다. Cycle_Time 등 현재 공정의 완결값을 사용하므로 생산 전 예측으로 해석하지 않는다. 센서 수신과 검사 확정의 실제 시각이 없어 이 시점의 운영 가능성은 현장 검증이 필요하다. 후속 검증에서는 PLC 기록시각, 수신시각, 검사 시작·확정시각을 각각 기록해야 한다.

### 연결 근거와 허용하지 않은 연결

두 파일의 Shot 감소 지점을 기준으로 run_id를 만들고 `(run_id, Shot)`을 연결했다. 품질 {{Q_N}}개 모두 일대일로 대응하고 공정 14개 열의 {{JOIN_VALUES}}개 값이 일치한다. 공정값을 중복 입력하지 않고 #41의 과거 이력과 감사용 정보를 추가했다. 과거 이력은 현재 행을 제외하고 구간마다 초기화한다.[L01]

파생 run_id는 실제 날짜나 설비 ID가 아니다. 값의 대응이 곧 동일 공장·설비·생산기간의 외부 인증을 뜻하지 않는다. 과거 팀 인수인계에는 #41/#42의 수집기간과 연계 시나리오가 적혀 있지만 원본 가이드를 다시 확보하지 못해 보조자료로만 취급했다. 물리 계보와 숫자 라벨 정의를 확인하기 전에는 운전조건 추천이나 단위 환산을 하지 않는다.

#40에는 line_no1, CylinderHead 및 2021년 8월 4일~10월 11일의 시각 기록이 있다. #41/#42와 대응하는 제품·설비·시점 키가 없으므로 행 조인을 하지 않았다. #40의 압력 기준이나 변수 중요도를 #42로 이식하지 않는다. 최소 2종 연계의 주 검증은 #42와 #41의 이력 추가 및 의사결정 결합이며, #40 단독 분석으로 이를 대체하지 않는다.

## 제2장 AI 모델 개발 및 통합성능 검증

### 비교 대상과 검증 설계

단일 데이터셋 기준 A0는 공정 14개 입력, A는 공정·센서·제품 코드·관측 순번의 22개 입력이다. 결합 B는 A에 정답을 쓰지 않는 #41 이력 4개를 추가한다. 설비 상태 Gate는 공정값과 과거 공정 이력으로 상태를 예측한다. Machine_Status, 원본 불량 열, y 타깃, oracle 이력과 원본 행 위치는 기본 품질 입력에서 제외했다.

기존 후보는 로지스틱 회귀, 랜덤포레스트, LightGBM, CatBoost를 비교하고 validation으로 선택했다. 5개 seed의 반복값을 기록했다. 모델군과 파라미터는 configs와 근거 파일에 고정돼 있다. seed 간 변동은 표본 신뢰구간과 다르다.[E01,R01]

within_run은 각 구간 내부 순서를 지킨 회고 평가이고, run_holdout은 구간 이동에 대한 시험이다. 둘 다 전체 파일의 미래만을 평가한 것은 아니다. forward_run은 앞선 구간으로 학습하고 다음 구간을 검증·시험한다. 원본 #41/#42에 날짜가 없어 이는 파일 순서에 대한 시간 가정이다. 같은 측정이 다른 역할로 들어가지 않도록 중복과 구간 경계를 점검했다.

기존 test는 이미 확인했다. 후속 선택을 train 내부 fit/calibration에 한정하고, 기존 validation을 바깥 개발 평가로 사용했다. 이후 결과는 새로운 독립 일반화 증거로 표현하지 않는다. 추가 정보가 생겨도 지금 결과에 맞춰 threshold나 성공 기준을 소급 조정하지 않는다.

### 품질 단독과 이력 결합의 전후 비교

| 기존 within_run test | AP | ROC AUC |
|---|---:|---:|
| A0 공정 단독 | {{A0_AP}} | {{A0_AUC}} |
| A 공정·센서 기준 | {{A_AP}} | {{A_AUC}} |
| B A와 #41 이력 결합 | {{B_AP}} | {{B_AUC}} |

표의 모집단은 {{OLD_TEST_N}} Shot, 양성 {{OLD_TEST_POS}}개이며 값은 seed별 지표의 평균이다. B-A AP 변화 {{B_AP_GAIN}}는 사전 개선 기준 0.02에 못 미친다. A0가 A보다 높았다는 점도 함께 공개한다. 센서나 이력을 더하면 성능이 반드시 좋아지는 것은 아니다. 평균 확률을 먼저 낸 뒤 재표집한 AP 차이와 이 표의 seed 지표 평균 차이는 서로 다른 추정량이므로 혼용하지 않는다.[E01]

미래 구간의 A ROC AUC는 fold 2/3/4/6에서 {{FWD_AUC_2}} / {{FWD_AUC_3}} / {{FWD_AUC_4}} / {{FWD_AUC_6}}다. Short_Shot 전문화의 개발 포착률 변화도 미래 적격 fold에서 {{Q1_GAIN_2}} / {{Q1_GAIN_6}}%p로 악화돼 test 평가를 생략했다. 성공한 하위집단만 전체 결과처럼 제시하지 않는다.[E01,E02]

### 상태 경보와 품질 검사의 의사결정 결합

보수적 Gate 선정은 기존 run_holdout의 공정 입력 관측 가능한 정상 {{GATE_NORMAL}}행 기준 FPR을 {{GATE_OLD}}%에서 {{GATE_NEW}}%로 낮췄다. 다만 관측 가능 {{GATE_OBS}}개·전체 {{GATE_TOTAL}}개 예열 에피소드 중 평균 {{GATE_EP}}개 탐지와 낮은 FPR 목표를 동시에 만족하지 못했다. 이 결과는 기존 test를 재사용한 평가이며, 아래 개발 queue와 모집단·모델이 달라 수치를 직접 차감하지 않는다.[E03]

별도의 중첩 개발 비교에서는 Q, GQ, OOD05, OOD1을 평가했다. Q는 입력 결손 보류와 품질 위험도 검사, GQ는 상태 경보 우선순위를 추가한 정책이다. OOD는 공정 범위를 벗어난 관측을 추가 보류한다. 로지스틱/LightGBM의 제한된 후보 중 내부 calibration에서만 선택했고 바깥 평가 전에 모든 선택을 잠갔다.

Q는 이번 개발 비교의 고정 단일 데이터셋 기준이며 모든 가능한 단독 정책 중 최적이라는 뜻은 아니다. A0의 기존 회고 AP가 더 높다는 이유로 바깥 개발 결과를 본 뒤 Q를 교체하지 않았다. 정책 계열 전체에 대한 우월성·열등성을 증명한 것으로 확대하지 않는다.

run 2의 양성은 {{RUN_3_POS}}개뿐이어서 소수 Shot의 검사 여부가 포착률을 크게 바꾼다. 네 구간을 같은 가중치로 평균하면 GQ-Q 차이는 +{{GAIN_MACRO}}%p지만, 실제 양성 수를 분모로 합치면 {{GAIN_POOLED}}%p다. 유리한 macro 평균만 채택하지 않는다. 4개 run을 짝지어 재표집한 조건부 구간은 [{{GAIN_LOW}}, {{GAIN_HIGH}}]%p로 0을 포함한다. 과거에 본 4개 개발 run과 고정 정책에 관한 구간이다.[E04]

분포 변화는 오경보의 후보 원인이다. 기존 오류 분석에 정상 공정값의 학습 범위 이탈률과 점수 이동을 기록했다. 그러나 범위 이탈이 제품 변경·센서 단위·실제 고장 중 무엇을 뜻하는지는 확정하지 못했다. 이 결과를 본 뒤 시험 구간에 맞춰 단위를 보정하거나 경계를 재탐색하지 않았다.

### 변수 기여와 인과의 구분

#40 정상압력 하위집단의 금형온도 6개 입력 제거에서 ROC AUC는 {{P40_FULL}}에서 {{P40_REMOVE}}로 낮아졌다. 이는 해당 데이터와 분할에서 변수 묶음의 예측 기여다. #42 결함의 원인, 다종 데이터의 전이 성공, 온도를 조정하면 불량이 줄어든다는 인과효과를 입증하지 않는다. 코드1을 불량으로 해석한 기존 라벨 의미의 원문 확인도 남아 있다.[E01]

기존 순열 중요도와 부분의존 분석은 상관된 공정 입력에서 대체 가능성·비현실적인 조합의 영향을 받는다. 낮거나 음의 중요도를 변수 무용성으로 단정하지 않는다. 설비·제품·단위가 확인되면 공정 전문가가 허용하는 변수 쌍과 범위를 먼저 정하고, 조건별 표본 수·양성 수·오차를 함께 제시하는 추가 상호작용 분석이 필요하다. 이번 초안에는 새 상호작용 효과나 운전 최적값을 만들지 않았다.

### 결측과 미관측 결과

#42와 연결된 상태는 모두 코드0이며, 코드1의 품질 정답은 {{WARM_Q}}행이다. 가생산 폐기라는 공개 설명을 개별 Shot의 품질 정답으로 복사하지 않았다. 입력 결손·상태 라벨 결측은 전체 운영 분모에 남기고, 정답이 있는 모집단에서만 품질 또는 상태 지표를 계산했다. 자동 탐지와 검사 도달은 서로 겹칠 수 있어 더하지 않는다.[L01,E04]

## 제4장 현장 적용 기본설계 및 KPI 개선효과

### 같은 검사 용량과 전체 분모

매 도착 기록까지 누적된 예산으로 검사 슬롯을 만들고 사용하지 못한 슬롯을 미래에 몰아 쓰지 않았다. 동일 Shot은 한 번만 검사한다. 보류 선착순, 상태 경보 위험도, 품질 위험도 순으로 우선순위를 정했다. 보류를 무료 처리나 정상 통과로 계산하지 않았다. 대기 지연은 기록 수이며 실제 분·시간으로 바꾸지 않았다.

20% 비교의 전체 모집단은 {{QUEUE_N}}기록, 알려진 정상은 {{QUEUE_NORMAL}}기록이다. 품질 정답이 있는 {{QUEUE_LABELLED}} Shot 중 양성은 {{QUEUE_POS}}개다. 에피소드는 전체 {{QUEUE_EP}}개와 공정 입력 관측 가능 {{QUEUE_OBS_EP}}개를 함께 보고한다.[E04]

| 정책 | 사용 검사 | 양성 포착률 | 정상 경보 또는 보류 | 미처리 보류 |
|---|---:|---:|---:|---:|
| Q | {{Q_INSPECTED}} | {{Q_CAPTURE}}% | {{Q_INTERVENTION}}% | {{Q_BACKLOG}} |
| GQ | {{GQ_INSPECTED}} | {{GQ_CAPTURE}}% | {{GQ_INTERVENTION}}% | {{GQ_BACKLOG}} |

모든 정책의 검사 슬롯 상한은 같지만 Q는 초기 후보 부재로 2슬롯을 사용하지 못했다. 표는 실제 사용량도 공개한다. GQ에서 OOD05로 바꾸면 전체 정상 기준 자동 FPR은 {{GQ_FPR}}%에서 {{OOD05_FPR}}%로 낮아진다. 동시에 자동 처리 가능 비율은 {{GQ_COVERAGE}}%에서 {{OOD05_COVERAGE}}%로 줄고 보류율은 {{GQ_HOLD_RATE}}%에서 {{OOD05_HOLD_RATE}}%로 증가한다. 낮아진 FPR만으로 안정적 운영을 주장할 수 없다.

자동 예열 탐지는 GQ 평균 {{GQ_AUTO_EP}}개, OOD05 {{OOD05_AUTO_EP}}개이고, 실제 검사 도달은 두 정책 모두 {{GQ_REACH_EP}}개다. 분모가 전체 {{QUEUE_EP}}개라는 점과 탐지/도달의 차이를 유지한다. 내부 정책 선택은 모든 fold에서 GQ였고, OOD 후보의 사전 순효과 기준은 충족하지 못했다. 따라서 OOD로 운영 정책을 교체하지 않는다.[E04]

### 비용 산식과 성립 조건

검사 한 건의 비용을 1로 정규화하고 다음 조건부 산식을 사용한다.[K01]

조건부 가치 차이 = r × s × 포착 양성Shot 차이 - 검사건수 차이 - p × 미처리 보류 차이

r은 회피 가능한 양성Shot 손실/검사비 비율, s는 검사 검출민감도, p는 미처리 보류 부담/검사비 비율이다. r=1/5/20/100, s=0.8/1, p=0/1/5를 가정해 비교했다. 실제 단가·민감도·구제 가능성을 측정한 것이 아니며 검사한 모든 양성이 실제 손실 회피로 이어진다는 보장도 없다.

20% 용량의 GQ는 Q보다 검사 {{EXTRA_INSPECT}}건을 더 쓰고 양성 Shot 포착 차이는 평균 {{CAPTURE_DELTA}}개다. r=20, s=1, p=0에서 품질·검사 부분의 가치 차이는 {{VALUE_DELTA}}검사비 단위다. 예열 검사 도달이 {{EXTRA_EP}}개 더 많아 이를 보충하려면 추가 도달 에피소드당 {{BREAK_EVEN}}검사비 단위 이상의 중복 없는 별도 편익이 필요하다. 그 편익은 현재 자료로 입증하지 못했다. 이 조건을 원화 절감액이나 ROI로 표현하지 않는다.

검사 3분 가정의 사용 인시는 GQ {{GQ_HOURS}}, 미처리 보류 추가 인시는 {{GQ_PENDING_HOURS}}다. OOD05의 미처리 보류는 {{OOD05_PENDING_HOURS}}인시다. 1분·5분 시나리오도 저장했다. 인시는 작업자 수·병렬성·교대와 도착률을 반영한 경과시간이 아니며 보류 재처리를 이미 사용한 검사량에 중복 계상하지 않는다.[K01]

### 현장 확인과 단계적 검증 계획

우선 기존 검사 방식과 제안 정책을 같은 도착 흐름에서 기록만 하는 shadow 평가로 비교한다. 검사자에게 모델 정답을 숨긴 상태에서 검사 결과를 확보하고, 미검사 표본도 사전 정한 비율로 독립 감사해 선택 편향을 확인한다. 이 과정에서 누락손실·검사시간·입력 지연·보류 해제를 기록한다.

원본 키·단위·라벨과 실제 입력 가용 시점이 확인되고, 현장 기준 대비 누락·정상 개입·대기·비용 제약을 동시에 만족할 때 제한된 보조 검사 시험을 검토한다. 제약의 수치는 현장 책임자와 실측 기준으로 먼저 고정한다. 현재 결과를 근거로 생산중지나 공정조건 변경을 자동 실행하지 않는다.

## 제5장 창의성 및 확장성

이 연구의 기여는 새 알고리즘의 발명보다 설비 상태와 품질 정답의 서로 다른 관측 범위를 구분하고, 보류와 경보가 같은 검사 용량을 소모하도록 만든 비교 설계에 있다. 다종 데이터 사용 자체를 성능 향상으로 취급하지 않고 단독 기준, 이력 결합, 의사결정 결합의 효과와 실패를 각각 남겼다.

다른 설비에 재사용할 수 있는 것은 원본 계보·열 허용목록·중복 및 키 검사·시간/그룹 분할·전체 분모·검사 queue·가정별 KPI 계산이다. 재사용할 수 없는 것은 현재 threshold, 파생 run 번호, 숫자 코드 해석, 공정값의 물리 범위와 비용 가정이다. 이 항목은 대상 설비의 식별자·단위·제품·검사 체계에 맞춰 다시 확인해야 한다.

#40의 별도 도메인 분석은 변수 기여와 스케일 차이를 확인하는 참고다. 외부 데이터에서 #42 모델의 성능을 검증한 것으로 표현하지 않는다. 제품·설비별 성능 차이를 분리해 보고할 표본이 부족하면 결과를 묶어 확장 성공을 주장하지 않고 추가 수집 대상으로 남긴다.
