# 미래 평가의 통계·운영 계획 — 아직 동결되지 않은 초안

이 문서는 새 라벨을 보기 전에 확정할 설계다. 새 성능 실험을 수행하거나 현재 결과에 맞춰 성공 기준을 변경하지 않는다. [입력 계약](FUTURE_EVALUATION_CONTRACT.md)과 함께 사용하되 최신 CSV 검증 명령은 `future_evaluation.py`다. 기존 v2 명령도 같은 revision 3을 호출하며 v1/v2 원본은 legacy/에 보존한다. [회차10 검사 범위](FUTURE_VALIDATION_REVIEW_ROUND10.md)는 표/파일 일치와 사람의 독립성 확인을 구분한다.

## 질문과 평가 대상

평가 질문은 같은 생산 흐름·입력 이용시점·검사 자원·대기/만료 조건에서, 고정한 품질 단독 정책 Q와 결합 정책 GQ가 FIFO보다 검사 완료 시점까지 포착하는 불량을 늘리는가이다. 현재3395기록/관측 양성505개의 포착률은 이 질문의 새 독립 평가가 아니다.

주 분석 모집단은 새 수집 기간의 **전체 생산 Shot**이다. run·제품·실제 설비/배치 키와 원본 식별자를 보존한다. 입력 누락, 예열, 정답 미관측을 사후 제외하지 않는다. 모집단 기간·마감 시각·비교할 정책 파일·결정시각·자원표·만료 규칙·가드레일을 새 라벨 열람 전에 고정한다. 실제 사업상 최소 개선 폭과 허용 검사 부담이 정해지지 않았으므로 숫자를 임의로 채우지 않는다.

## 검사를 배정한 효과와 생산을 바꾼 효과를 구분

첫 단계는 생산 제어를 바꾸지 않는 **shadow 평가**다. 생산 완료 시점의 품질을 독립 감사로 확인하고, 정책은 동일 흐름에 대한 가상 검사 순서만 출력한다. 검사나 재작업이 원래 품질 라벨을 바꾸지 않도록 검사 전 상태의 정의·측정 절차를 고정해야 한다. 온라인 정지·속도 변경·재작업이 다음 Shot에 영향을 미치면 고정 흐름 replay로 인과 효과를 추정할 수 없다. 그 단계는 별도의 현장 개입 설계가 필요하다.

감사 자원은 정책 자원과 분리한다는 현재 계약을 실제로 만족해야 한다. 독립 감사에 든 시간·비용도 추후 전체 실증 비용으로 기록한다. 이를 무료 자원으로 간주해 ROI를 높이지 않는다. 감사가 동일 검사 설비를 점유한다면 현재 계약은 미지원이므로 자원 공유 설계를 먼저 검토한다.

## 전수 또는 확률 감사의 지표

전수이면 전체 생산의 품질을 확인해 직접 포착률을 계산한다. 확률 감사이면 전체 생산 프레임의 각 Shot i에 사전에 정한 포함확률 π_i>0를 기록하고, 정책·결과와 독립적으로 선택한다. 현재 구현의 hash-Bernoulli는 공통 확률만 지원한다. 고정 seed·변경 불가능한 원본 키·추출 전 기록이 필요하며 이름만 hash라고 붙였다고 독립성이 증명되지는 않는다.

포함확률의 역수를 설계 가중치로 쓰는 기본 원칙은 Statistics Canada의 *Survey Methods and Practices*, 7.1을 따른다. 아래 식은 이 프로젝트의 고정 정책 비교에 적용한 설계 초안이다. [Statistics Canada 원문, PDF p130~131](https://www150.statcan.gc.ca/n1/en/pub/12-587-x/12-587-x2003001-eng.pdf#page=130).

감사선택 I_i, 생산 시점 불량 y_i, 고정 정책 p의 기한 내 검사완료 지시자 d_pi를 사용한다.

```text
추정 전체 불량 수 D_hat = Σ I_i × y_i / π_i
추정 정책 포착 수 H_hat(p) = Σ I_i × y_i × d_pi / π_i
추정 포착률 R_hat(p) = H_hat(p) / D_hat
쌍별 차이 Δ_hat(p,FIFO) = Σ I_i × y_i × (d_pi − d_FIFO,i) / π_i / D_hat
```

가중 총량의 설계 불편성과 비율의 정확한 불편성은 다르다. 비율은 유한표본에서 편향될 수 있다. `D_hat=0`이면0%나 동등으로 표시하지 않고 추정 불가로 처리한다. 공통 확률이면 비율에서 가중치가 약분되지만 추출확률·표본수·미관측 프레임을 생략하지 않는다. 두 정책에는 같은 감사표본을 사용하고 차이의 공분산을 유지한다. 정책이 검사한 행의 라벨만 모은 자료로 이 지표를 대체하지 않는다.

## 불확실성과 다중 비교

먼저 해당 수집 기간의 유한 모집단에 대한 감사 추출 오차와, 다른 미래 구간으로의 일반화 오차를 구분한다. 전수라도 다른 기간 일반화가 입증되는 것은 아니다. 확률 감사의 분산은 실제 추출 설계에 맞춰 계산하며, 시간 의존·제품 구성·run 차이를 지우는 행 단위 iid bootstrap을 기본값으로 사용하지 않는다. 가상 seed 반복을 독립 생산 표본으로 세지 않는다.

정책의 점수와 배정을 고정한 조건부 분석인지, 재학습·재배정을 포함하는 분석인지 명시한다. 본 초안의 주 비교는 고정 정책의 쌍별 차이다. 현재의4개 run을 재사용한 구간 재표본 범위는 새로운 일반화CI 또는 새 실증의 검정력 근거가 아니다. 새 수집의 run 수·사건 수·상관구조·감사 응답률과 사업상 최소 효과가 정해진 뒤 표본 계획과 구간 추정 방법을 확정한다. 임의의 최소 run 수를 합격선으로 만들지 않는다.

주 비교 하나와 가드레일을 사전에 정하고, 나머지 정책·제품/불량 하위집단은 보조 분석으로 구분한다. 여러 기준 중 유리한 것만 골라 성공으로 발표하지 않는다. 주 비교가 Q인가 GQ인가, 최소 유효 개선과 정상 부담 상한은 **아직 미결정**이며 현장 질문으로 남긴다. 결과를 보며 모집 기간을 늘리거나 중단하면 사전 순차 설계가 없는 한 확증 판정을 하지 않는다.

## 데이터 누락·종료·중단 규칙

선정된 감사표본의 검사와 라벨이 cutoff까지 모두 도착해야 현재 계약이 통과한다. 누락을 정상으로 대체하거나 사후 재추출하지 않는다. 누락이 생기면 원인·단계·구간별 분모를 보고하고 주 분석을 보류한다. 비응답 보정을 도입하려면 별도의 사전 검토가 필요하다. 대기 만료·overflow·종료 잔량은 모든 정책에서 동일한 규칙을 적용한다.

다음 조건 중 하나라도 미충족이면 성능 판정을 시작하지 않는다: 새 자료의 독립성, 전체 생산 프레임, 원본/시계의 진실성, 실제 입력 사용 확인, 독립 감사, 용량/만료의 현장 적합성, 라벨 전 프로토콜 고정. 코드 통과만으로 이 조건들의 진실성을 인증하지 않는다.

## 현재 가능한 다음 개선

발표·원고·Q&A·근거 검수와 검증기 버그 수정은 새 성능자료 없이도 계속한다. 성능·ROI·생산 제어의 효과 주장은 실제 자료가 준비된 뒤에만 평가한다. 이 문서를 사전등록 완료나 현장 합의 완료로 표현하지 않는다.
