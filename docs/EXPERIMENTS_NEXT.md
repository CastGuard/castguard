## 공통 규칙

- 기존 원본·전처리·분할·보고서를 덮어쓰지 않는다. 후속 설정과 산출물은 `configs/oct03_*.json`, `reports/oct03/` 등 별도 위치에 저장한다. 해당 경로는 예정이며 아직 파일이 생긴 것은 아니다.
- 후보·입력·라벨·선정 기준·실패 조건·예산을 실행 전에 기록한다. 모든 후보/기각 결과와 행 단위 예측을 보존한다. 이미 본 test를 기준으로 후보·임계값을 바꾸지 않는다.
- 개발 선택은 각 fold의 train/validation에서만 한다. 나중 구간의 표본·라벨·통계를 앞선 forward fold의 입력 선정·학습·임계값 결정에 쓰지 않는다. test 재평가는 같은 test를 재사용한 탐색 결과임을 표시한다.
- 새로운 독립 데이터가 없으면 확증·현장 개선·새 공장 전이 성공을 주장하지 않는다. 같은 원본을 다시 분할한 것을 새로운 독립 데이터로 부르지 않는다.
- 모델 성과는 동일 표본·검사 예산·seed의 비교로 보고한다. 전체 평균과 구간별 결과·분모·최악 구간을 함께 제시한다. 표본 부족은 성공이 아니라 `미측정/판정 불가`다.
- 기존 목표(AUC .70/.75, AP 양성률 2/2.5배, B AP +.02, Gate FPR ≤2%)는 유지한다. 아래 검사 포착률 기준은 별도 연구 우선순위 판정 기준이며 원래 목표 달성을 대체하지 않는다.

## Q1 · 구체 불량의 검사 가치

**가설:** 전체 불량을 하나로 합쳤을 때 약했던 신호가 특정 불량에서는 같은 검사 예산의 포착률을 개선한다.

1. 각 fold의 train/validation에서 Short_Shot, Bubble, Exfoliation, Blow_Hole 및 Product_Type별 행 수·양성 수·중복 유형·결측을 기록한다. test 표본 수는 최종 설명에 병기하되 후보 선정에 쓰지 않는다.
2. 네 유형을 사전에 고정한 후보로 둔다. 유형별 train에 양성/음성 각각 50개 이상, validation에 각각 20개 이상인 fold만 개발 비교에 사용한다. 이는 작은 표본의 낙관적 채택을 줄이는 내부 하한이며 충분한 검정력을 보장하지 않는다. 부족한 유형도 표본표에 남긴다.
3. 입력 A와 기존 고정 설정의 로지스틱/LightGBM만 비교한다. 제품별로 추가 모델을 무제한 늘리지 않고 우선 층별 오류를 보고한다. 최대 4유형 × 2모델 × 5seed × 기존 11fold = **440회 학습**이며 표본 미달은 건너뛴다. 추가 feature/하이퍼파라미터 탐색은 하지 않는다.
4. 비교 기준은 같은 유형 정답에 대한 **기존 전체 불량 모델의 순위**와 **무작위 검사 기대값**이다. 기준 모델도 같은 fold의 validation으로만 선택한다. 유형별 모델이 쉬운 라벨을 골라 AUC를 높인 것과 기존 정책의 검사 효용 개선을 구분한다.
5. 각 fold에서 상위 `floor(n × b)`개를 검사한다. `b = 10%, 20%, 30%`; 동률은 고정 `row_id` 순서. 포착률은 검사된 양성 / 평가 전체 양성, 누락률은 1−포착률, lift는 포착률 / 실제 검사율이다. 전체 불량과 대상 유형의 포착률을 모두 보고한다. 유형 하나의 개선 때문에 다른 불량을 더 놓치는지 확인한다.

**개발 판정:** 20% 검사 예산에서 기존 기준 모델과 무작위 기대값을 모두 상회하고, 기준 모델 대비 평균 포착률이 **5%p 이상** 개선되며, 평가 가능한 forward validation fold가 2개 이상이고 그 각각에서 차이가 음수가 아니면 다음 통합 비교 후보로 올린다. seed 평균·구간별 차이·블록 불확실성을 같이 기록한다. 이 5%p는 비용 정보 확보 전의 내부 연구 문턱이며 통계적 유의성/실제 이익의 보증이 아니다. 구간이 적거나 불확실성이 0을 포함하면 `일부 근거`로 둔다.

후보 선택 후 기존 test를 한 번 재평가한다. 재사용 test에서 실패하면 결과와 한계를 남기고 재튜닝하지 않는다. 개발 통과만으로 실용화나 원래 전체 불량 목표의 달성을 선언하지 않는다. 10/3 안에 적격 후보가 없으면 범위를 억지로 더 잘게 나누지 않는다.

## G1 · 정상 경보 부담을 제한한 Gate

**가설:** validation AP 중심 선정에서 벗어나 정상 FPR와 예열 에피소드 포착을 함께 평가하면 보수적 보조 경보 정책을 만들 수 있다.

- 기존 Gate 후보의 학습/validation 예측을 우선 재사용한다. 비교 정책은 ① 기존 AP 선정+전체 정상 FPR 2% 임계값, ② 모델과 임계값을 구간별 정상 FPR 및 에피소드 탐지로 선정하는 보수적 정책, ③ 공정 변수 하나를 쓰는 단순 규칙이다. 단순 규칙의 변수·방향은 train에서 정하고 경계는 validation에서만 정한다. test를 보고 규칙을 고르지 않는다.
- 정책 ②는 개발에서 각 관측 가능한 validation 구간의 정상 FPR ≤2%를 만족하는 후보 중 관측 에피소드 포착률 최대, 지연 최소, 높은 임계값, 고정 모델명 순으로 선택한다. 제약을 만족하면서 예열을 하나도 못 잡으면 무경보 정책으로 명시한다. validation 에피소드가 부족하면 판정 불가다.
- 검사 예산과 경보를 혼동하지 않는다. 정상 경보 수/정상 관측 Shot 수, 예열 검출 Shot 수, 관측 가능/전체 에피소드 분모, 탐지 지연, 결측 보류 수를 모두 기록한다. 경고로 이름을 바꾸어 정상 경보 부담이 사라졌다고 계산하지 않는다.
- 기존 run_holdout/forward 결과를 재사용 test로 한 번 평가한다. **정상 FPR ≤2%와 최소 16/20 에피소드 탐지**를 동시에 충족하는지 확인하고, 대상권 내부 목표 18/20 및 평균 지연 ≤3 Shot을 별도 표시한다. 20은 현재 관측 가능 에피소드 수, 전체는 21이다. 모집단이 바뀌면 분모·비교 가능성을 다시 명시한다.
- pooled FPR뿐 아니라 구간별 FPR·정상 표본 수·불확실성을 공개한다. 특정 구간이 2%를 넘으면 모든 구간에서 제약을 만족했다고 주장하지 않는다. test에서 실패하면 이 결과에 맞춰 임계값을 다시 맞추지 않는다.

**판정:** 조건을 함께 만족하지 못하면 자동 생산중지의 핵심 근거에서 제외한다. 낮은 부담의 보조 경고에도 유의미한 이익이 없으면 핵심 솔루션에서 내려놓는다. 상태 탐지 성능을 실제 불량 감소로 치환하지 않는다.
